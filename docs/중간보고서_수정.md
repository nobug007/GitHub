# [SafeFinder] 스마트 트래커 복합 안심존 및 노인돌봄 관제 시스템 개발 중간보고서 (수정본)

> **이 문서의 수정 방향**: 기존 초안은 하드웨어/펌웨어/백엔드가 모두 완성된 것처럼 서술되어 있었습니다. 실제 개발 현황(2026-07-04 기준)에 맞춰 **완료 / 진행중 / 예정**을 명확히 구분해 다시 작성했습니다.
> - **하드웨어(웨어러블 ESP32 플랫폼)**: 구성품 개별 테스트 완료, 통합 조립 진행 중

> - **xAPI/LRS 변환 모듈, ZBI 설문 엔진, React 웹 대시보드**: 설계/계획 단계 (아직 코드로 존재하지 않음)

## 1. 서론

### 1.1 프로젝트 배경

전 세계에서 가장 빠르게 초고령사회로 진입하고 있는 대한민국과 일본은 치매 돌봄 및 환자 실종이라는 무겁고 공통된 사회적 과제에 직면해 있습니다. 보건복지부의 최신 법정통계에 따르면 국내 65세 이상 노인의 치매 유병률은 9.25%에 달하며, 2026년 올해를 기점으로 국내 치매 환자 수는 역사상 처음으로 100만 명(약 101만 명)을 돌파했습니다. 이에 따른 실종 사고 또한 폭증하여 2024년 기준 한국의 치매 환자 실종 신고는 1만 5,502건으로 전체 실종의 31%를 차지하는 심각한 수준에 이르렀습니다. 약 20년 먼저 초고령화가 진행된 일본의 경우 치매 환자가 약 700만 명에 육박하며 2024년 실종 신고는 1만 8,121명으로 사상 최고치를 경신했습니다. 양국 도합 매년 3만 3,000건 이상의 실종 위험이 상시 발생하고 있는 실정입니다.

치매로 인한 국가적 관리 비용이 국내에서만 연간 22조 9,000억 원(GDP의 약 1%)에 육박하는 상황에서, 일본 후생노동성의 선행 연구는 치매 사회적 비용(총 14조 5,000억 엔) 중 가족들의 무급 노동에 의존하는 '비공식 돌봄 비용'이 6조 1,600억 엔으로 공식 의료비의 3배를 넘어선다는 점을 보여줍니다. 국내 지역사회 거주 치매 가족의 45.8%가 극심한 간병 부담을 호소하고 있으며, 돌봄 중단의 가장 큰 사유가 "24시간 독점 감시의 한계(27.2%)"로 나타났습니다.

기존 배회감지기·스마트워치는 (1) 매일~2~3일마다 충전해야 하는 부담, (2) 안전구역을 완전히 이탈한 뒤에야 대응하는 사후 대응 방식이라는 두 가지 치명적 한계를 가지고 있습니다. 본 프로젝트는 이 두 문제를 동시에 해결하는 '사전 예방·차단' 시스템을 목표로 합니다.

### 1.2 프로젝트 목적

'SafeFinder' 솔루션의 Phase 1 목표는 **① 안전 로직(안전구역 판정·이탈 감지·보호자 알림)을 소프트웨어로 먼저 완성·검증**하고, **② 이를 저전력 웨어러블 하드웨어로 포팅**하는 것입니다. 현재 ①은 완료되어 실사용 테스트 중이며, ②는 부품 통합 단계입니다.

## 3. 시스템 개요 (실제 구현 기준)

### 3.1 전체 시스템 구성

현재 실제로 동작하는 SafeFinder 소프트웨어 시스템은 4개의 안드로이드 앱과 1개의 백엔드로 구성됩니다.

| 컴포넌트 | 역할 | 상태 |
|---|---|---|
| **SFC** | 보호자/케어기버용 컴패니언 앱. 어르신 상태 대시보드, 보호자·안전구역 관리, 신규 기기 BLE 온보딩 | ✅ 구현 완료 |
| **SFD** | 추적 대상 기기(현재는 폰) 앱. BLE 온보딩 수신, WiFi/BLE/GPS 안전구역 판정, 낙상·이탈 감지, SMS 경보 | ✅ 구현 완료 |
| **SFW** | 온보딩 전용 경량 기기 앱 (추적 로직 없이 등록만) | ✅ 구현 완료 |
| **SFD_Test** | SFD의 텔레메트리 경로만 뗀 테스트용 경량 변형 | ✅ 구현 완료 |
| 백엔드 API | `sf-api.ese-lab.com` — 기기 등록, 텔레메트리 수신, elder/guardian/safezone CRUD | ✅ 구현 완료(실제 Swagger 스펙 확인) |
| 웨어러블 HW (ESP32/GPS/LTE-M) | 최종 착용형 단말기 | 🔧 부품 테스트 완료, 통합 조립 진행 중 |
| 임베디드 펌웨어 | Deep Sleep, LTE-M 핸드오버, OTA 등 | 📋 착수 예정 |
| xAPI/LRS 변환, ZBI 설문 엔진, React 웹 대시보드 | 표준화·정량효과측정·웹UI | 📋 설계 단계 |

### 3.2 주요 기능 (실제 구현된 것 중심)

**3.2.1 BLE 기반 기기 온보딩** — SFC가 BLE로 SFD/SFW를 스캔·연결하여 어르신 정보/보호자/안전구역 설정을 청크 단위로 전송하고, 기기가 이를 받아 백엔드에 자체 등록합니다.

**3.2.2 다중 안전구역 판정 (WiFi → BLE → GPS)** — SFD는 WiFi 안전구역(2분 유예), 보호자 폰과의 BLE 근접(2분 유예), GPS 기반 이동거리 판정을 우선순위대로 적용해 안전구역 재실 여부를 결정합니다.

**3.2.3 낙상·이탈 2단계 알림** — 안전구역 이탈 후 5분 미확인 시 **WARNING**, 30분 시 **EMERGENCY(SOS)**로 격상되며, 보호자 전화번호로 **SMS를 직접 발송**하는 동시에 백엔드로 telemetry를 전송합니다.

**3.2.4 자이로 기반 움직임 감지** — 폰 내장 자이로/가속도계로 60초 주기 활동량을 샘플링하여 telemetry에 포함합니다.

**3.2.5 서비스 복원력** — 텔레메트리 서비스가 종료되면 `AlarmManager`로 자동 재시작을 예약해 재부팅/시스템 강제종료에도 감시가 끊기지 않도록 합니다.

### 3.3 시스템 동작 시나리오 (실제 코드 기준)

① **최초 온보딩**: SFC에서 BLE 스캔 → 기기 선택 → 서버에서 deviceId 발급 → 어르신/보호자/WiFi 정보 입력 → BLE로 SFD/SFW에 config 전송(청크 분할) → SFD/SFW가 자체적으로 서버에 등록 → SFC가 ACK 폴링으로 등록 완료 확인

② **평시 안전구역 체류**: SFD가 WiFi(등록된 AP) 또는 BLE(보호자 폰과 근접)를 통해 안전구역 재실을 판정. 순간적인 연결 끊김은 2분 유예 기간 동안 무시(오탐 방지)

③ **이탈 전조 감지(1단계 Warning)**: 안전구역 이탈 후 5분간 미복귀 시 보호자에게 SMS 발송 + 서버로 위험 telemetry 전송

④ **이탈 확정(2단계 Emergency/SOS)**: 30분 미복귀 시 최고 위험도로 격상, 60초 주기로 SMS·telemetry 반복 발송

⑤ **서비스 복원**: 폰 재부팅이나 OS의 강제 종료로 서비스가 죽어도 알람 기반으로 자동 재시작

### 4.2 실제 API 스키마 (Swagger 기준)

*(기존 초안의 API 예시 JSON 12종 — deviceId 발급, config 조회(`GetConfig`), elderId 조회, 피보호자 등록/조회, 로그 페이징 조회, 최신 위치/배터리 조회, 안전구역 목록/추가, 트래커 데이터 저장, 원시 로그 검색 — 은 실제 Swagger 스펙과 일치하므로 그대로 유지합니다. 상세 내용은 원본 4.2절 참조.)*

## 6. S/W 구성 (SFC/SFD 중심 — 실제 구현 상세)

> 📸 **캡쳐 필요 위치 표시**: 아래 각 화면 설명 옆에 `[CAPTURE: ...]`로 표시했습니다. 실제 갤럭시 S24 울트라에서 해당 화면을 캡쳐해 이미지로 교체해 주세요.

### 6.1 SFC (보호자 앱) — 실제 구현

SFC는 단순 "설정 도구"가 아니라 **보호자가 상시 사용하는 케어 대시보드**입니다. `MainActivity.kt` 한 파일(~1,870줄)에 아래 화면들이 모두 구현되어 있습니다.

| 화면 | 설명 | 관련 함수 |
|---|---|---|
| 페어링/BLE 스캔 | 신규 기기 탐색·선택 | `showBlePickerDialog()` |
| 기기 등록 폼 | 어르신/보호자/WiFi 정보 입력 후 BLE 전송 | `showRegistrationForm()`, `sendConfig()` |
| **홈 대시보드** | 어르신 실시간 상태(재실/이탈), 배터리, 최근 로그 | `renderHome()` |
| 안전구역 목록/추가/수정/삭제 | WiFi/BLE/GPS 안전구역 CRUD | `showSafeZoneList()`, `showSafeZoneAddForm()` |
| 보호자 목록/추가/수정/삭제 | 다중 보호자 등록·관리 | `showGuardianList()`, `showGuardianEditForm()` |

`[CAPTURE: SFC 홈 대시보드 화면 — renderHome() 실행 결과]`
`[CAPTURE: SFC 안전구역 목록 화면 — showSafeZoneList()]`
`[CAPTURE: SFC BLE 기기 탐색 다이얼로그 — showBlePickerDialog()]`

### 6.2 SFD (추적 기기 로직 앱) — 실제 구현

SFD는 최종 임베디드 하드웨어로 포팅될 **안전 감시 로직의 소프트웨어 레퍼런스 구현체**입니다. `SfdTelemetryService.kt`(~650줄)가 핵심입니다.

| 화면/기능 | 설명 | 관련 함수/파일 |
|---|---|---|
| 셋업 화면 | BLE 온보딩 대기 상태 표시 | `renderSetupScreen()` |
| **운영 화면** | BLE/GPS 상태 chip, 연결된 보호자 폰, WiFi AP 정보, Config Sync 버튼 | `renderOperationScreen()` |
| 안전구역 판정 상태머신 | WiFi→BLE→GPS 순 판정, 유예시간 처리 | `updateLocationState()`, `effectiveWifiStatus()` |
| 낙상/이탈 경보 | WARNING(5분)/EMERGENCY(30분) SMS+telemetry | `sendStatusSms()`, `sendRiskTelemetry()` |
| 서비스 복원 | AlarmManager 기반 자동 재시작 | `SfdRestartReceiver.kt` |

`[CAPTURE: SFD 운영 화면 — renderOperationScreen(), BLE ON/GPS 상태 chip 포함]`
`[CAPTURE: SFD 셋업 화면 — 온보딩 대기 상태]`

**최근 검증/버그 수정 이력(실사용 테스트 진행 근거)**: 실제 테스트 중 "안전구역 안에 있는데도 이탈→재진입이 반복되는" 오탐 현상을 발견 → BLE 안전구역 판정에 WiFi와 동일한 2분 유예 로직이 없었던 것이 원인임을 코드 분석으로 특정 → `SfdStore.kt`에 grace-period 로직을 추가해 수정 완료. (이는 시스템이 이미 실사용 수준으로 테스트되고 있음을 보여주는 근거입니다.)

### 6.3 SFW / SFD_Test — 보조 구현체

- **SFW**: SFD와 동일한 BLE 프로토콜로 온보딩만 수행하고 서버에 자체 등록하는 경량 기기 앱 (안전구역/텔레메트리 로직 없음)
- **SFD_Test**: SFD의 텔레메트리/API 경로만 검증하기 위한 테스트용 경량 변형

### 6.4 백엔드 API

`https://sf-api.ese-lab.com/api/v1/*` — 기기 등록(`/devices/register`), 텔레메트리(`/telemetry`), config 조회(`Device/getConfig`), elder/guardian/safezone CRUD, 로그 조회 API가 실제로 동작 중이며 Swagger 문서로 확인 가능합니다.
